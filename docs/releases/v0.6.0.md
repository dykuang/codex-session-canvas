# Codex Session Canvas v0.6.0 — development acceptance record

Milestone: [0.6.0](https://github.com/dykuang/codex-session-canvas/milestone/3). Issues: #31 → #32 → #33 → (#34 / #35) → #36.

**This release adds read-only user-provided ChatGPT metadata snapshots to a local Codex graph. It does not have a supported general live API to enumerate private ChatGPT projects/conversations.** No cloud account authentication, browser scraping, private endpoints or raw ChatGPT data ZIP parsing is used.

## What changed

- #31: `docs/v0.6-access-decision.md` documents the evidence and explicit **snapshot-only** integration decision.
- #32: `docs/chatgpt-snapshot-v1.md`, optional `chatgptProjectId` registry field and source-qualified identity prevent duplicate IDs, name-based joining or invented parentage.
- #33: `chatgpt_metadata.py` implements schema validation, multi-page merging, strict allowlisted fields, deduplication, archived-unknown, invalid/unavailable/incomplete/stale states, and read-only refresh. Data is not silently transformed from raw chat exports.
- #34: `chatgpt_bridge.py` merges cloud chat cards with unchanged Codex source IDs and project groupings. ChatGPT source titles are shown only for explicitly ID-mapped mirrors. Unmapped projects and unassigned chats stay separate.
- #35: browser graph shows type/evidence for imported relationships and preserves browser-local handoff/reference/manual edges. Imported cloud cards are **not** passed to Codex resume or unverified deep links.
- #36: Windows-compatible CLI setup, tests, browser workflow and privacy documentation.

### Windows runtime limitations

The CI Windows runner is a clean ephemeral VM with artificial data. It **does not** establish that the user-installed Codex Desktop/CLI, a personal ChatGPT account, or OAuth/live data access works. Live cloud access is intentionally unsupported. Outstanding hardware/runtime validation from #20–#23 remains tracked separately.

## Privacy and rollback

Ordinary canvas open/refresh uses local Codex session metadata plus the explicitly selected snapshot's allowlisted metadata. Snapshot import will reject message/turn/body/content keys; no real conversation is modified. The old opt-in Context Graph body reader is separate and requires explicit approval. Do not supply raw account exports; create independently verified metadata-only records.

Back up installed Skill, `~/.codex-session-canvas/projects.json`, local Context Graph records and snapshot JSON before upgrading. To revert to v0.5, restore the prior Skill and remove the optional `chatgptProjectId` property from a **copy** of the registry (older validation cannot recognize it). Snapshot files are read-only and can simply be left unconfigured.
