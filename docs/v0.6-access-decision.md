# v0.6 / Issue #31: ChatGPT metadata access decision

Status: **snapshot-only integration** for the standalone local Python canvas (2026-11-24).

## Supported-access investigation

| Requirement | Verified standalone interface | Decision |
|---|---|---|
| List ChatGPT consumer Projects and project IDs | No documented general-purpose API usable by this local app | Do not call private endpoints |
| List all active/archived personal ChatGPT conversations | No supported standalone enumeration method demonstrated | Use user-provided metadata-only snapshot |
| Paginate cloud listings / monitor updates | No supported standalone pagination or incremental cursor demonstrated | Versioned, explicitly marked complete/incomplete snapshot pages |
| Project title / relationship metadata | Not guaranteed by published export format | Require supplied project IDs + titles; leave relationships unknown unless independently sourced |
| Authentication | No supported local-app OAuth/token scope demonstrated for this purpose | No credentials, cookies, bearer tokens, proxying or browser scraping |
| Windows local smoke | No access to the user's installed Windows runtime in this environment | Limit verification to fixture-based Windows path tests; record real runtime as unverified |

OpenAI's documented **Settings → Data controls → Export data** / Privacy Portal flow can supply an account export. The export includes conversation **content**, not an authenticated read-only project-graph metadata endpoint. **Do not feed raw export ZIP or `conversations.json` directly to this tool.** Its exact project membership and branch/parent fields are not guaranteed by the documentation. Extract only an independently verified metadata-only listing or manually create a snapshot from authorized source fields.

References:
- https://help.openai.com/en/articles/7260999-exporting-your-chatgpt-history-and-data
- https://help.openai.com/en/articles/10169521-projects-in-chatgpt

## Selected integration contract

1. The canvas remains **offline-first**. Existing local Codex JSONL scanning is unchanged and never opens conversation bodies.
2. A user explicitly supplies a **v1 metadata-only JSON snapshot**, optionally with paginated records (see `docs/chatgpt-snapshot-v1.md` and `examples/chatgpt-metadata-v1.json`).
3. The reader strictly validates and projects allowlisted fields; unknown keys, any message/content structures, malformed references or oversized inputs are rejected. No credentials or message bodies are cached, logged, exposed through the server or exported.
4. Snapshot import is read-only and opt-in. The canvas displays a source label, freshness timestamp, archived/unknown state, pagination completeness and warnings. A later import/refresh is a fresh read of the explicitly configured file, not an account sync.
5. Cloud projects can be matched to local logical projects **only by an explicit source project ID**. Equality of display names or nearby timestamps is never sufficient.
6. Relationship edges are shown only when provenance is explicit. Lack of source relationship evidence means **unknown**; user-created/manual edges remain distinct and reversible.

## Failure and privacy guarantees

- Missing or invalid snapshot: local Codex sessions remain available; cloud status is unavailable/invalid.
- Partial pages: imported records can be displayed, but the import must say **incomplete**, never masquerade as a complete listing.
- Archive information not included: show **unknown**, never infer from missing records.
- Deleted/unavailable cloud conversations: preserve only local manual annotations; do not guess identities, query content, or mutate an account.
- No installed ChatGPT login is inspected; no secret files, cookies or private endpoints are used.

**Out of scope / not verified:** live cloud API read, Windows account-authenticated smoke, actual membership and conversation ancestry from an export lacking documented metadata. These are intentionally not claimed in v0.6.
